# 후속 확장 전략

## 원칙

v1이 실제로 쓰인 뒤 반복 입력의 불편을 근거로 확장한다. 예정 기능을 이유로 지금 전체 금융 원장을 만들지 않는다.

## 상세 거래 가져오기

계좌/card ID, 외부 provider와 외부 거래 ID, 원본 파일 hash, import batch ID를 adapter에서 관리한다.
거래내역으로 계산한 잔액은 기존 snapshot의 대조 후보이며 사용자 확정치를 자동 덮어쓰지 않는다.
수동 보험금/고정 납부와 매칭할 때 원본 현금기록에 연결하고 새 수입/지출을 중복 생성하지 않는다.
같은 날짜·금액만으로 중복을 확정하지 않는다. 취소·부분 취소·결제일 차이를 고려한다.

## Android 알림 수집

추후 별도 권한과 명시적 사용 동의를 거치는 Kotlin 수집기를 검토한다.
현재 앱이 일반 문자나 다른 앱 알림을 이미 읽는 것처럼 설명하지 않는다.
수집 내용은 최소화하고 카드번호/OTP/비밀이 유입될 수 있는 경로를 별도 위협모델로 검토한다.
처음부터 모든 알림을 서버에 보내지 않는다.

## OCR·AI

영수증·약관을 입력 초안으로 해석할 수 있으나 저장 금액·보상결정은 사용자 확인이 필요하다.
의료/금융 문서를 외부 모델에 자동 전송하지 않는다. 모델 공급자·데이터 정책·동의·보관을 별도 검토한다.
개발 에이전트를 사용하는 것과 운영 데이터에 AI를 사용하는 것은 다른 결정이다.

## 투자·연금

종목별 보유내역·수익률·환율을 추가할 때 계좌 총 평가액 중복을 막는다.
납입/인출/평가변화를 구분할 충분한 데이터 없이는 정확한 투자수익률을 계산한다고 주장하지 않는다.
예상 국민연금/노후 현금흐름은 현재 자산과 다른 리포트로 다룬다.

## 기존 프로젝트 연계

FamilyCard 등 기존 프로젝트와의 연동은 후속 검토 항목이다.
실제 API/데이터 권한/유지관리 상태를 확인하기 전 의존성을 만들지 않는다.
새 제품 개발이 기존 프로젝트의 재작성·자동 병합을 뜻하지 않는다.

## 보안 범위 변화

타인에게 서비스 제공, 결제대행, 클라우드 CVC 동기화, 공개 사용자 가입은 단순 기능 플래그가 아니다.
신뢰 경계·운영 책임·표준 적용을 다시 검토하며 기존 개인기기 예외 설명을 재사용하지 않는다.
