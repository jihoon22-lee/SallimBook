# 테스트 전략·출시 인수 기준

이 문서의 테스트는 **개발해야 할 기준**이다. 초기 문서 패키지에서 앱 테스트가 이미 수행되었다는 뜻이 아니다.

## 1. 계층

| 계층 | 도구/대상 | 필수 검증 |
|---|---|---|
| 도메인 | pytest | 순자산·기간·원리금·보험금·재고 계산 |
| DB/API | pytest + PostgreSQL | FK, 트랜잭션, 가계 격리, 충돌, 재시도 |
| 웹 | Vitest + Playwright | 폼, 조회·수정, 상태, 핵심 사용자 여정 |
| Android | Kotlin 단위·계측, 실기기 | bridge, 지문/키, 잠금·백업·서명 |
| 운영 | 별도 복구 환경 | 백업 복원, API/앱 호환, 장애 복구 |
| 문서 도구 | Python unittest | 게시기 dry-run/충돌/중복 방지, 링크·계획 유효성 |

## 2. 계산 테스트 벡터

| 테스트 ID | 입력 | 기대 결과 |

| T-01 | 자산 100,000,000 / 부채 30,000,000 | 순자산 70,000,000 |
| T-02 | 같은 계좌가 계좌·자산 화면에 표시 | 가계 합계에는 한 번 |
| T-03 | 주택 600,000,000 × 가계 지분 0.5 | 300,000,000; 부부 표시로 재합산 안 함 |
| T-04 | 연금계좌 총액 20,000,000과 내부 ETF 참고 15,000,000 | 자산 합계 20,000,000 |
| T-05 | 전월 존재, 이번 월 미입력 | null/미확인, 0원 감소로 표시 안 함 |
| T-06 | 첫 월 기록 | 비교 없음, 가짜 0% 증가 없음 |
| T-07 | 기존 보유 계좌 뒤늦게 10,000,000 등록 | 범위 변경 안내, 자동 저축액 취급 금지 |
| T-08 | 수입 3,000,000 기록, 계좌 스냅샷 5,000,000 | 스냅샷 그대로 5,000,000 |
| T-09 | 원리금 1,000,000=700,000+300,000 | 납부 1,000,000, 소비성 300,000, 부채 snapshot 불변 |
| T-10 | 매월 31일 규칙, 평년 2월과 3월 | 2/28, 3/31; 복수 회차 생성해도 각각 한 건 |

| T-12 | 의료비 30,000+860,000+20,000+25,000+25,000 | 960,000 |

| T-14 | 보험금 600,000+200,000 | 수령 800,000, 부담 160,000 |
| T-15 | T-14에서 병원 환불 10,000 | 순의료비 950,000, 부담 150,000 |
| T-16 | T-15에서 보험사 반환 50,000 | 순수령 750,000, 부담 200,000 |
| T-17 | 의료비 100,000, 정액 수령 150,000 | 부담 -50,000 허용 |
| T-18 | 입금 500,000 → 사건 A 300,000/B 200,000 | 월 유입500,000, 사건별300,000/200,000 |

| T-20 | 필터3개 입고 후1개 교체 | 재고2개, 입고로 교체일 변경 없음 |

| T-24 | 과거 자산월 선택 | 소모품 상태는 여전히 오늘 |

## 3. 보험 트리·입력

비용 없는 처방 노드, 입원 합계와 설명용 수술비 분해, 부분 환불, 청구 없는 직접 지급,
여러 계약·여러 사건 배분·분할 입금·반환·치료와 정산 상태 분리를 검증한다.
부모를 자손 밑으로 이동, 다른 사건으로 참조 연결, 비용이 있는 노드의 무단 삭제는 실패해야 한다.
진료비 원본과 청구 연결 JOIN으로 SUM이 늘어나는 회귀 테스트를 둔다.

## 4. 보안 테스트

- 로그인 미인증/만료, 다른 가계 ID, revoked 기기, CSRF, 로그인 rate limit.
- 패스키 잘못된 RP/origin/challenge, 재사용 challenge, UV 누락.
- 카드 목록·HTML·Query cache·스크린샷 fixture·logcat·서버로그에 PAN 평문 없음.
- Android 네이티브 bridge는 비밀을 반환하지 않고 허용되지 않은 URL/ID를 거부.
- 잘못된 보관함 암호, AAD/tag 변조, nonce 재사용, key_version mismatch.
- 지문 취소/잠금/미등록/새 지문 등록/기기 잠금수단 제거/화면회전/백그라운드/강제종료.
- 생체인증 성공 플래그만 위조해도 비밀이 해제되지 않음.
- 앱 재설치·기기 이전·클라우드 백업·앱 내보내기에 CVC가 포함되지 않음.
- 새로운 구성원 및 기기 wrapping, 복구코드 교체, 키 회전 중 장애 복구.
- 외부 첨부 URL/경로조작/다른 사용자 파일/HTML 파일 업로드 실패.

## 5. 합성 데이터와 증거

기본 fixture는 부부 A/B, 공동 가계 H1, 공격 검증용 별도 가계 H2, 더미 금융기관·의료기관만 사용한다.
보안 스크린샷과 로그는 더미 값으로 생성하고 실제 카드 정보를 CI artifact에 업로드하지 않는다.
테스트 결과에는 실행한 commit, 환경, 기기/API 수준, 명령, 성공/실패, 제한을 남긴다.
에뮬레이터 통과와 실기기 통과를 별도 필드로 기록한다.

## 6. CI 목표

기초 구현 이후 PR 파이프라인: 문서·린트 → 타입 → 단위 → PostgreSQL API/migration → 웹 E2E → Android compile/unit.
실기기 보안 테스트와 운영 복구는 별도 릴리스 게이트다.
의존성/비밀 검사, Action 버전 고정, 최소 token 권한, 외부 PR의 secret 접근 차단을 포함한다.
초기 패키지에 workflow YAML은 포함하지 않는다. 실제 프로젝트 manifest가 마련된 뒤 동작 가능한 CI만 추가한다.

## 7. v1 사용자 인수 시나리오

두 실제 Android 기기와 PC 브라우저에서 합성 데이터로 시작한다.
계좌/카드/연금/부채 등록 → 두 달 자산 비교 → 부부 수입과 고정비 → 보험계약과 사건/비용/지급 → 소모품 입고/교체를 완료한다.
양쪽 계정의 갱신·충돌·권한, 비밀 표시·복구, 백업 후 새 서버 복원을 검증한다.
7개 영역 중 하나라도 빠지면 전체 v1 인수를 완료하지 않는다.
