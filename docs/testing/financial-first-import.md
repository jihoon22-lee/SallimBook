## 변경

- 연회비와 가족카드 여부의 nullable 전용 필드, 기존 메모 보존.
- 보관함 시작 시 입력 영역 스크롤과 초점 이동.
- 웹/Android 공유 CVC v2 암호문, 유지/교체/삭제 구분과 저장 범위 동의.
- v1 호환 읽기·회전, v2→v1 덮어쓰기 차단. 0023 downgrade는 v2 행이 남으면 중단.

- 현재 예상 월 수입과 성과연도 상여 원본 분리. 지급월의 확인된 양수 현금만 연결.
- 세전/세후 현금/주식 수령 당시 평가액/지급률 및 null/0 구분.
- 정정 시 연결 현금과 원본을 함께 변경, 반환 존재·기존 수동 상여 중복은409로 차단.
- 일반 감사는 필드명, 내보내기는 원본과 JSON 문자열 형태의 immutable revision 보존.

## 독립 검토

별도 읽기 전용 에이전트가 TS/Kotlin 암호 경로와 서버 및 상여 현금 연결을 검토했다.
외부 인증 또는 실기기 검증은 아니다. 다음 P2 지적을 수정하고 합성 회귀를 추가했다.

1. 일괄 일부 성공 뒤 재진입: 최신 목록에서 이미 저장된 카드를 제외하고 닫기에도 목록 재조회.
2. 상여 원본 추가 시 기존 수동 현금과 중복: 같은 구성원·지급월 활성 상여가 있으면409.
3. 연결된 현금에 일반 정정/무효 버튼 노출: 서버 capability를 false로 반환하고 상여 화면 안내.

지급월을 모르는 확정 수령 사실과 별도 연결 동의의 분리는 후속 설계 범위다. 현재 received는
지급월·현금 확인 및 연결 동의를 의미하며 미상 월을 만들어 넣지 않는다.

## 운영 적용

0022→0023→0024 순서로 전용 DB를 migration한 뒤 같은 소스의 API/웹 및 서명 APK를 제공한다.
구 APK는 공유 CVC v2를 읽을 수 없으므로 새 APK 제공이 필요하다. 기존 로컬 CVC는 자동
업로드하지 않으며 envelope 변경 후 무효화될 수 있다. 운영 백업에는 공유 CVC 암호문이
포함되고 사용자 내보내기에는 보관함 전체를 제외한다.

실제 데이터 등록은 배포 인수 후 기존 ID에 이어서 처리한다. 보관함 암호와 복구코드는
사용자가 직접 설정·보관하며 DB 직접 삽입으로 인증과 키 생성을 우회하지 않는다.
