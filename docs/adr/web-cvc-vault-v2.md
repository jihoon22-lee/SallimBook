# ADR — 웹 CVC 입력과 공유 보관함 payload v2

상태: 사용자 결정 채택, 구현·검증 진행. 날짜: 2026-10-31. 연결: #181, R-09/R-10/R-12/R-20.

## 결정과 이전 원칙

사용자가 웹에서도 CVC를 입력하고 기존 자료를 반복 입력하지 않도록 요청했다. ADR 0004의
Android 로컬 전용 제한을 **선택적인 공유 보관함 CVC**로 대체한다. 서버 일반 카드 필드나
평문 CVC API는 추가하지 않는다. 기존 로컬 CVC 기능은 별개로 유지한다.

## 포맷

wrapping/key-check와 `format_version=1`은 그대로 유지한다. `payload_schema_version`은
1 또는 2이며 엄격한 정수다. 카드 AAD의 마지막 u32는 해당 payload schema다. 기존
`SallimBook/vault/card/v1` prefix는 바꾸지 않는다.

SBV1 27바이트/암호문 43바이트는 계속 읽고 회전한다. SBV2는 기존 위치의 magic만 SBV2로
바꾸고 끝에 CVC 길이 1바이트와 ASCII 숫자 공간 4바이트를 추가한 정확히 32바이트다.
CVC 길이는 0/3/4이며 나머지는 NUL padding이다. 암호문+tag는 48바이트로 CVC 유무와
자리수가 서버에 노출되지 않는다. 새 편집은 v2를 쓰고 회전은 원본 버전과 bytes를 보존한다.

서버는 schema/암호문 길이 조합 (1,43)/(2,48)을 검사한다. v2 현재 envelope를 v1으로
덮어쓰는 요청을 거부하고, 회전 대상은 원본 schema와 같아야 한다. CVC 삭제는 v2의 길이
0으로 명시적으로 저장한다. 수정 UI는 유지/교체/삭제를 구분한다.

## 접근과 삭제

공유 CVC는 보관함 공유를 받은 구성원과 복구 수단 소유자가 복호화할 수 있다. 입력 전에
이 범위를 알리고 동의를 받는다. 웹에서는 전용 화면 DOM/ref와 소유 bytes에만 비밀을 두며
일반 React state·스토리지·캐시·로그에 넣지 않는다. 창 이탈·취소·실패·만료 시 정리한다.
Android 입력·복호화·표시는 네이티브 화면으로 제한하며 JS bridge에 평문을 반환하지 않는다.

Android 로컬 CVC를 자동 업로드하지 않는다. 기존 로컬 CVC가 envelope revision 변경 시
무효화되는 정책은 유지한다. 웹에서 카드 비밀을 수정하면 기존 로컬 값이 더는 유효하지 않을
수 있음을 안내한다. 로컬 값과 공유 값을 하나로 합치거나 어느 값이 최신인지 추론하지 않는다.

운영 백업과 envelope 이력에는 CVC가 포함된 암호문이 남을 수 있다. 사용자 평문 내보내기에는
보관함 전체를 계속 제외한다. 현재 CVC 삭제는 이전 백업의 소급 삭제를 의미하지 않는다.

## 배포와 검증

서버 additive migration과 양방향 읽기 가능한 Android 제공 후 웹 v2 쓰기를 제공한다.
v2 저장 후 구 서버/구 APK로 단순 복귀할 수 없다. downgrade는 v2 행이 있으면 중단한다.
TS/Kotlin 공통 합성 벡터·API/DB 권한/409/멱등·mixed-schema 회전·복구·웹 잠금·네이티브
소유 배열 초기화·내보내기 제외를 검증한다. 독립 보안 리뷰와 실기기 시험 결과를 따로 기록한다.
