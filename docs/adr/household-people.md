# 가족과 로그인 구성원 분리

- 상태: 채택
- 날짜: 2026-10-24
- 관련: Issue #141, R-01, R-02, R-13, R-14, R-19, R-20, R-21

보험의 환자·피보험자에 자녀·부모 등 비로그인 가족을 추가한다. 로그인은 기존처럼
부부 두 계정과 공동 가계 하나다. 계약자, 금융상품 소유자, 금전 기록 작성자,
보관함 구성원과 감사 작성자의 의미는 확장하지 않는다.

## 모델과 기존 기록

`household_people`는 보험 대상이다. 로그인 구성원은 `id = member_id`로 연결하며 이름은
현재 users 이름을 조회한다. 비로그인 가족은 별도 UUID, 이름, 자녀/부모/기타 관계,
보관 시각과 version을 갖는다. 같은 이름의 서로 다른 사람을 허용하고 화면에서 중복
이름을 안내한다. 가족에게 사용자·세션·구성원 슬롯·보관함 권한을 만들지 않는다.

0019 마이그레이션은 비활성 구성원을 포함한 모든 household_members를 같은 UUID로
복사하고 다음 세 복합 FK의 대상만 people로 바꾼다.

- insurance_policies.insured_member_id
- insurance_cases.patient_member_id
- insurance_case_revisions.patient_member_id

보험 기록과 불변 사건 revision의 값을 UPDATE하지 않으며 불변 보호 트리거를 완화하지
않는다. `policyholder_member_id`는 household_members를 계속 참조한다. API/DB의 기존
`*_member_id` 이름은 호환을 위해 유지하는 명명 부채이며 OpenAPI에 실제 people 의미를
기록한다. 사용자 등록과 초대 수락은 같은 트랜잭션에서 연결된 person을 생성한다.

가족은 삭제 대신 보관한다. 새 환자·피보험자 선택에는 활성 person을 요구하지만 기존
보관된 person을 유지하는 내용 수정, 사건 재개방, 비용·청구·지급 기록은 허용한다.
이름·관계·보관 변경은 If-Match와 감사 기록을 사용한다. 등록은 Idempotency-Key와 DB
고유 제약으로 재전송을 한 번 처리하고, 최초 `{id,version}`만 반환한다. 재시도 후에는
현재 목록을 다시 조회한다. 가족 ID는 actor나 owner ID로 사용할 수 없다.

## 구버전 앱과 웹

새 웹과 APK는 `X-SallimBook-People: 1`을 보낸다. 이 표시는 선택 UI와 감사 어휘 지원
여부이며 인증이나 권한의 증명이 아니다. 기존 `X-SallimBook-Native: 1`은 변경하지 않는다.
헤더가 없는 구 앱·캐시된 웹이 비로그인 가족을 새로 지정하거나, 기존 가족을 다른 사람
또는 null로 바꾸려 하면 422로 거부한다. 같은 가족 ID 유지와 관련 없는 수정은 허용한다.
기존 로그인 구성원끼리의 동작은 유지한다.

0.1.9 앱은 가족 이름과 선택 UI를 지원하지 않는다. 가족 사건은 '구성원 확인 필요' 등으로
보일 수 있고 필수 select 때문에 사건 편집을 마치지 못할 수 있다. 가족 기능 전체에는
새 APK 설치 또는 새 웹 접속이 필요하다. APK 게시만으로 설치 완료를 가정하지 않는다.

0.1.9의 엄격한 감사 어휘 검증을 위해 헤더 없는 native audit 조회는 0.1.9에 알려진
entity/action/changed-fields만 **SQL에서 페이지 제한 전에** 선택한다. cursor에는 이
조회 모드도 묶는다. 기존 앱은 가족 이벤트가 제외됐다는 안내를 표시할 수 없다.
따라서 **0.1.9 설정 → 감사 이력은 가족 이벤트를 표시 없이 제외한다. 웹·새 APK에서
전체 기록을 확인해야 한다.** 원본 DB와 내보내기에서는 제외하지 않는다. 서버의
`audit/legacy_native.py` 어휘는 고정하며 새 릴리스 어휘와 함께 늘리지 않는다.

## 배포·복구·검증

API를 정지한 유지보수 구간에서 백업 후 0019를 적용하고 새 서버와 웹을 기동한다.
새 APK를 배포하고 위 구버전 제약을 알린다. 가족 데이터가 생기기 전에는 0018로
downgrade할 수 있다. 비로그인 가족 행이 하나라도 있으면 downgrade는 거부되며
순방향 수정한다. 데이터를 지우고 되돌리는 방법을 사용하지 않는다.

운영 업그레이드 리허설은 실제 이전 schema revision으로 되돌린다. 기존 테이블의
행 개수·해시를 보존하고 people 추가분은 모든 구성원과 일대일로 정확히 일치하는지
별도 확인한다. 가족 생성 후 downgrade 거부와 사건 revision 바이트 보존은 API DB
회귀로 확인한다. 실제 실행한 명령과 결과는 연결 PR에 기록한다. Android JVM·모의
bridge 검증과 실제 Galaxy 인수 시험은 구분한다.
