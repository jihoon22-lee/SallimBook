# 보험 계약·사건·진료 화면 검증

SB-019/SB-020, Issues #28/#29, R-13/R-14/R-18.
보험 계약과 보장, 기존 고정 납부 규칙을 사용하는 보험료 연결, 독립 사건과 진료 트리를 웹과 Android adapter에 연결했다.
이 문서는 계약·사건 단계의 checkpoint다. 비용·청구·실제 수령/반환 화면의 SB-021/SB-022 연결과 통합 검증은 이어서 진행한다.

계약·보장·납입 기간은 각각 입력한다. 보장금액 미입력과 명시적 0원을 구분하며 확인한 환급·적립 자산만 연결한다.
보험료 편집은 같은 recurring rule 상세/변경 경로를 사용한다. 연결 해제는 규칙이나 과거 납부를 삭제하지 않는다.
사건은 보험계약과 독립이며 치료/정산 상태를 따로 관리한다. 사건 변경 사유와 당시 상태·진단·작성자·시각을 이력으로 조회한다.
진단 설명/코드는 사건 목록에 표시하지 않는다.

진료 트리는 모든 페이지를 읽고 외래·입원·수술·처방·약국·추적 외래·그룹을 표시한다.
기본 펼침 깊이와 최대 인라인 깊이를 제한하고 각 노드 상세에서 하위 트리·상위 경로·상위 이동을 제공한다.
드래그 없이 부모 선택으로 이동하며 자신과 자손을 선택 목록에서 제외한다. 서버가 최종 권한·순환·참조를 검증한다.
진료 노드 생성은 금전 이벤트를 만들지 않는다. 하위 진료/비용이 있는 노드 삭제는 거부한다.

Android 증권번호는 네이티브 보호 화면에서만 입력·표시한다. metadata 요청은 policy_number를 포함하지 않는다.
웹에서는 별도 일시 입력 DOM과 출력 DOM만 사용하고 React state/브라우저 저장소에 전체 번호를 넣지 않는다.
표시는 최대 30초이며 blur/pagehide/visibility/unmount/버전 갱신 시 지운다. 늦은 응답과 취소된 응답도 다시 표시하지 않는다.
서버 recent-login이 만료되면 재인증을 안내한다. 지원되지 않는 증권번호 전용 패스키 scope를 만들지 않는다.

변경에는 자원 If-Match를 사용하고 충돌 후 작성 내용을 보존한다. 최신 내용과 비교한 뒤 변경한 필드만 유지한다.
멱등키가 없는 metadata 생성의 네트워크 결과가 불확실하면 목록 확인을 요구하며 자동 재전송하지 않는다.
