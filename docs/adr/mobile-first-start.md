# ADR 0008 — 모바일에서 직접 시작하고 배우자 연결

상태: 채택 · 2026-10-18 · Issue #87 · R-01/R-02 · SB-005/007/034/039/040.

## 문제와 사용자 결정

첫 계정을 만들기 위해 운영 CLI, PC에서 받은 15분 코드, 별도 로그인까지 요구하는 흐름은
부부가 모바일에서 바로 사용하려는 요구에 맞지 않았다. 사용자는 웹과 앱 어느 쪽에서도
직접 시작할 수 있어야 한다고 명시했다. 기존 보안 문서의 CLI 전용 최초 등록 정책을 변경한다.

부부 2계정·공동 가계 1개는 유지한다. 계정은 변경자를 구분하고 금융·건강정보 접근을 제어하는
가계 안의 두 사용자다. 별도 외부 서비스 회원가입이나 이메일 인증을 요구하지 않는다.

## 시작과 연결

- 처음 시작하는 사람은 모바일 웹·PC 웹 또는 Android에서 이름과 비밀번호를 설정한다.
  로그인 이름은 `owner`, 새 가계 이름은 `우리 가계`다. 이미 만들어 둔 빈 가계는 이름과 ID를 보존한다.
- 서버가 계정·구성원·기기·세션을 같은 트랜잭션에서 만들고 바로 로그인시킨다. 홈으로 이동한다.
- 첫 구성원은 최근 재인증 후 배우자 연결 코드를 만든다. 배우자는 8자리 코드·이름·비밀번호를
  입력하여 로그인 이름 `partner`로 같은 가계에 연결되고 바로 로그인한다.
- 기존 로그인·패스키·긴 초대 API는 유지한다. 기존 첫 계정의 로그인 이름이 `partner`여서
  새 기본 이름과 충돌하는 경우에는 기존 초대 방식으로 다른 로그인 이름을 지정할 수 있다.
- 응답이 끊겨 등록 완료 여부가 불명확하면 기존 계정의 로그인 경로로 확인한다. 계정이나
  가계를 지우거나 다시 초기화해서 해결하지 않는다.

## 최초 시작의 신뢰 경계

서버의 최초 시작은 기본 비활성화한다. 배포 manifest가 `setup_identity_sha256`을 명시해야 한다.
이 값은 Tailscale Serve가 전달하는 정확한 `Tailscale-User-Login` 헤더 값의 SHA-256이다.
API는 실제 ASGI peer IP가 전용 Docker DNS의 `node` 주소인지 확인한 뒤 헤더를 대조한다.
누락·중복·빈 값·다른 사용자·Funnel 표시·DNS 실패·다른 peer를 모두 거부한다.
`X-Forwarded-For`와 클라이언트가 보낸 인증 성공 플래그를 신뢰하지 않는다.

고정 Tailscale v1.104.1은 수신 요청의 사용자 헤더를 먼저 지우고, 사설망의 인증된 사용자
정보로 새 값을 설정한다. tagged 기기와 Funnel에는 사용자 헤더를 설정하지 않는다.
비 ASCII 값은 RFC 2047 Q 인코딩이므로 인코딩된 실제 헤더를 기준으로 한다.
[공식 설명](https://tailscale.com/docs/features/tailscale-serve#identity-headers)과
[고정 버전 구현](https://github.com/tailscale/tailscale/blob/v1.104.1/ipn/ipnlocal/serve.go#L1023-L1064)을 확인했다.

이 신뢰는 Caddy가 전용 node 네트워크 공간의 loopback에만 bind하고, API 포트를 호스트에
노출하지 않으며, Uvicorn의 `--no-proxy-headers`를 유지한다는 배포 조건에 의존한다.
프록시를 바꾸면 설정만 복사하지 말고 이 경계를 다시 검증한다. 공개 443은 앱 연결 JSON만 제공한다.

첫 시작은 설치 단위 advisory lock과 가계 행 잠금으로 직렬화한다. **사용자 또는 구성원이
단 하나라도 존재하면 비활성화/폐기 상태와 관계없이 첫 시작을 다시 열지 않는다.** 기존 CLI
초대 수락도 같은 가계 잠금과 함께 직렬화하고, 첫 시작 성공 시 오래된 미사용 초대를 폐기한다.

## 배우자 코드와 비밀 처리

연결 코드는 15분·한 번 사용이며 서버에는 해시만 저장한다. 재발급은 이전 미사용 초대를 폐기하고
과거 코드를 재사용하지 않는다. 서버 전체에서 15분 동안 최대 5번 연결을 시도할 수 있고,
웹/native 전환·주소 변경·코드 재발급으로 이 한도를 초기화하지 않는다. 긴 세션·refresh·기존
초대 토큰 검증은 32자 이상으로 유지하여 짧은 코드를 다른 인증 경로에 사용할 수 없게 한다.
두 계정 제한, 발급자의 활성 owner 여부, 가계→초대 잠금 순서를 유지한다.

Android의 이름·비밀번호·코드 입력 및 코드 표시는 네이티브 보호 화면에서 처리한다.
JS에는 시작 가능 여부와 완료/취소 상태만 반환한다. 웹은 비밀번호·코드를 영구 저장하지 않고
코드 표시는 최대 30초 및 화면 이탈 시 지운다. 이 변경은 보관함 암호·CVC 활성화 조건을 바꾸지 않는다.
