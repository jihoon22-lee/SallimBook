# 보험 사건·진료 트리·청구·지급 흐름

모든 금액·이름·날짜는 설계용 합성 예시다. 실제 진료 기록이나 보장 가능성 판단이 아니다.

## 1. 기본 사건

```text
피지낭종 진료 및 수술 [환자: 구성원 A]
├─ 첫 외래
│  ├─ 진료·검사 지불 30,000원
│  └─ 처방전 (별도 지불 없음)
├─ 입원 및 수술
│  ├─ 입원 영수증 지불 860,000원
│  └─ 수술 설명/확인서 (위 비용과 중복 합산하지 않음)
├─ 약국
│  └─ 처방약 지불 20,000원
└─ 수술 후 외래
   ├─ 1차 재진 지불 25,000원
   └─ 2차 재진 지불 25,000원
```

총 실제 지불금은 960,000원이다. 처방 자체는 무금액 노드이고 약국 결제는 실제 비용이다.
입원·수술·외래와 첨부 문서를 같은 트리에서 보되, 집계는 실제 비용 행만 대상으로 한다.

## 2. 계약과 청구

사건은 특정 보험계약 하위에 종속되지 않는다.
A계약 실손 청구와 B계약 정액 수술비 청구를 동일 사건에 연결할 수 있다.
두 청구가 같은 입원 영수증을 근거로 사용하더라도 총지출이 1,820,000원으로 증가하면 안 된다.
청구상태는 초안/접수/추가서류/심사/결과확인/종료 등으로 관리하며 지급 상태를 별도로 보여준다.
'청구 완료'와 '지급 완료'가 자동 동의어가 되지 않게 한다.
계약이 해지·만기·실효된 뒤에도 종료 전 진료의 청구를 새로 기록할 수 있다. 계약 선택에는 상태가 함께 보이고 안내 문구가 붙지만 저장을 막지 않는다([ADR 0009](adr/late-insurance-records.md)).
의료비 화면은 그 비용을 현재 근거로 인용한 청구 목록을 보여준다. 인용 청구가 있는 비용은 청구 근거를 먼저 정정한 뒤 정정·무효한다.

## 3. 지급 기록

실제 입금 A 600,000원(의료비 보전), 실제 입금 B 200,000원(정액).
순보험금 수령 800,000원, 사건 순현금부담 160,000원이다.
청구를 입력하지 않았어도 '지급 기록 추가'에서 사건·보험사/계약·유형·금액·입금계좌로 기록할 수 있다.
나중에 접수번호를 알면 지급 배분을 기존 청구에 연결한다. 새 입금을 또 만들지 않는다.
종료된 계약에 대한 직접 배분도 같은 방법으로 기록한다. 늦게 들어온 입금도 실제 입금일로 기록하며 계약 상태로 거부하지 않는다.
청구 상세는 그 청구에 연결된 배분의 실제 수령·반환·순수령만 보여준다. 심사 결정액이나 다른 청구의 입금을 섞지 않는다.

### 분할 지급

입금 300,000원과 입금 300,000원은 별도 원본이다.
동일 청구에 배분되면 수령액 600,000원으로 계산한다.
심사 결정액 600,000원을 실제 입금 300,000원에 다시 더하지 않는다.

### 한 입금이 여러 사건에 해당

입금 500,000원 중 사건 A 300,000원, 사건 B 200,000원으로 배분한다.
월간 보험금 수입은 500,000원 1건, 사건별 통계는 각각 배분액이다.
배분 합계가 500,000원과 다르면 저장하지 않거나 초안으로만 유지하며 확정 통계에는 넣지 않는다.

## 4. 환불·반환

병원 환불 10,000원이 발생하면 순의료비는 950,000원, 다른 조건이 같으면 순현금부담 150,000원이다.
보험사에 50,000원을 반환하면 순보험금은 750,000원, 순현금부담은 200,000원이다.
반환은 실제 반환 날짜와 원래 지급/배분에 연결하고 원래 입금 행을 삭제하지 않는다.
병원 환불과 보험사 지급 반환은 서로 다른 분류다.
환불·반환을 정정할 때 처음 기록한 사유는 그대로 남고, 정정 시 입력한 사유는 해당 금전 이력의 정정 사유로 남는다. 사유 자체가 틀렸다면 무효 처리 후 새로 기록한다.

보험금이 의료비보다 많아지면 음수 순현금부담을 그대로 보여주고 정액 보장 수령액을 구분한다.
이 결과만으로 부당수령 또는 환급 의무를 판단하지 않는다.

## 5. 사건 종료

치료 종료와 청구 정산 종료는 별도 상태다.
치료 종료 후 추가 보험금이 들어오거나 같은 사건 재진이 생기면 이력을 보존하며 상태를 다시 열 수 있다.
추가 진료가 기존 사건인지 새로운 사건인지는 사용자가 선택한다.
질병명/코드가 같다고 자동으로 다른 사건을 합치지 않는다.

## 6. 증빙·파일

문서는 사건, 진료 노드, 개별 비용, 청구, 계약에 연결할 수 있다.
파일 원본은 한 번 저장하고 여러 link를 통해 참조할 수 있다.
영수증 업로드만으로 금액을 자동 확정하지 않는다. v1은 직접 입력이다.
진단명은 목록/알림/로그에 과도하게 노출하지 않고 잠긴 화면 알림에는 일반 문구를 사용한다.

## 7. 연결 화면

사건 비용 → 결제 카드/계좌 상세.
보험금 지급 → 입금계좌 상세 및 월간 수입의 보험금 행.
계약 → 납부 고정비와 해당 계약 청구 목록.
홈 → 진행 사건 수와 확인할 지급/추가서류 알림(보조 영역).

모든 링크는 같은 원본을 표시하는 내비게이션이며 별도 금전 기록을 생성하지 않는다.
