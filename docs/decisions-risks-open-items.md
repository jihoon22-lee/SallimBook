# 결정·위험·미확정 사항

## 1. 확정 요구사항

SallimBook 이름, 7개 필수 영역, Android 중심·PC 웹 동등 핵심 기능,
부부 2계정·공동 가계 1개, 월간 자산/소모품 중심 홈,
수동 입력 우선, 금융 자동 수집 후속,
보험 사건 트리·수동 지급, 증권·연금·IRP 계좌,
번호/유효기간 보호·재인증 및 Android 로컬 CVC.
기술 방향은 React/Capacitor/Kotlin + FastAPI/PostgreSQL이다.

## 2. 설계자가 선택한 기본값

| 항목 | 기본 제안 | 바꾸는 절차 |
|---|---|---|
| 저장소 공개 범위 | private | 소유자의 명시적 변경 결정 |
| 운영 | 상시 호스트 + HTTPS | 인프라 Issue에서 실제 환경 확정 |
| 날짜·통화 | Asia/Seoul, KRW | 기존 기록 변환 영향 검토 |
| 오프라인 | online-first | 동기화/암호화 ADR 필요 |
| 비밀 표시 | 최대30초, 이탈 즉시잠금 | 보안·사용성 검토 |
| 앱 잠금 | 백그라운드1분 후 | 기기 실사용 검토 |
| Android 최소 | API30 제안 | 두 기기 지원 확인 후 확정 |
| 키 파생 | PBKDF2-HMAC-SHA256≥600k 후보 | 성능/암호호환/보안 리뷰 |

## 3. 개발 전에 확인할 항목

O-01 실제 운영 서버·도메인·외부 접근 방식.
O-02 두 Android 기기 버전, 생체인증 강도·기기 잠금 정책.
O-03 실제 package/applicationId와 release 서명키 보관자.
O-04 초대/초기 계정 등록 절차와 복구코드 보관 방법.
O-05 선정 라이브러리의 정확한 지원 버전과 라이선스.
O-06 오픈소스 라이선스 부여 여부. 현재 자동 부여하지 않는다.
O-07 CVC 개인기기 보관의 위험·백업제외·지원범위에 대한 구현 검토.

이 항목들은 제품 설계를 다시 묻기 위한 반복 질문이 아니다.
해당 개발 Issue의 준비 조건으로 기록하고, 확인 전에는 더미 환경으로 독립 작업을 진행한다.
실제 비밀번호·카드값·서명키를 채팅으로 요청하지 않는다.

## 4. 위험과 대응

| 위험 | 영향 | 대응·게이트 |
|---|---|---|
| 마스킹만 하고 원문 노출 | 계정/카드 유출 | 일반 API 원문 없음, native display, 검증 G4 |
| 공유 vault 키 복구 실패 | 카드정보 접근 상실 | member/recovery/device wrapping, 복원 시험 |
| 지문 성공을 로그인으로 오해 | 계정 사칭 | 인증 층 분리, challenge/세션 검증 |
| 보험 다중청구 조인 중복 | 지출/수입 오집계 | 원본과 배분 분리, 고정 테스트 벡터 |
| snapshot과 현금 기록 혼합 | 잔액 이중 증가 | 명확한 기준원본, 자동 가감 금지 |
| 고정비/보험료 독립 중복 | 금액 불일치 | 단일 recurring rule version |
| 재고 동시 소모 | 음수 재고 | DB lock + 멱등키 |
| Android·웹 버전 차이 | 데이터 손상 | versioned API·하위 호환 |
| 운영 PC 종료 | 어디서든 접근 불가 | 개발/운영 분리 |
| 의료 첨부 공개 | 건강정보 유출 | 권한 다운로드·비공개 저장·로그 최소화 |
| 뒤늦은 자산 등록 | 증가율 왜곡 | 비교범위 변화와 동일범위 비교 |

## 5. 변경 관리

요구사항 변경은 R-ID 영향, DB/API/보안 영향, migration, 테스트 변경을 명시한다.
중요한 선택은 docs/adr에 새 문서를 추가하고 기존 결정을 지워 없애지 않는다.
마일스톤 완료는 문서 작성이 아니라 인수 기준 충족으로 판단한다.
