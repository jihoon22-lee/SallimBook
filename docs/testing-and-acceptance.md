# 테스트 전략·출시 인수 기준

이 문서는 제품 인수 기준이다. 실제 실행 근거는 [요구사항 추적표](requirements-traceability.md)의
도메인별 기록에 연결하며, 자동 테스트 통과와 실제 기기·운영·출시 인수를 구분한다.

## 구현된 검사 기반

SB-004의 [공유 합성 fixture](../packages/test-fixtures/README.md)는 H1/H2와 T-01~T-24의
입력·기대 결과를 JSON으로 제공한다. fixture 구조·금액·관계 검사 47개는 예제 자체의 일관성 검사이며,
아래 제품 인수 완료를 뜻하지 않는다. 각 vector의 제품 인수 상태는 현재 `pending`이다.

GitHub Actions는 문서·도구(운영 도구 시험 포함), API lint/단위(`ops/`·`tests/operations` lint 포함), 격리 문서 검사 도구,
웹 린트(ESLint·jsx-a11y)·타입·OpenAPI 생성 drift, PostgreSQL migration/API, 이전 schema(0014_vault)에서 합성 행을 올리는
업그레이드(`api-upgrade`), 운영 이미지 빌드(`ops-images`: `ops/Dockerfile.*`를 빌드하고 게시하지 않으며 실제 Caddy 경로를 검사),
PC·모바일 viewport 웹 동작·실제 HTTPS, Android 개발 빌드의 9개 job을 정의한다.
`api-upgrade`는 migration 시험의 합성 시드 세 건을 이름으로 지정해 실행하고 skip이면 실패한다. 실제 이전 릴리스 이미지로 하는
업그레이드 리허설(`ops.test_upgrade`)은 이미지 두 개와 ClamAV 빌드가 필요해 운영자가 직접 실행한다.
main push의 CI는 취소되지 않고 새 push에 밀려 대기 중 취소되지도 않는다. pull request만 새 commit이 이전 실행을 취소한다.
동일 PostgreSQL 이미지 digest와 frozen 의존성을 사용하며 저장소 비밀·서명키·실데이터를 주입하지 않는다.
DB 테스트 미설정 skip, Android `NO-SOURCE`, 모바일 viewport는 각각 실제 DB·단위·실기기 통과와 구분한다.
실기기 실패 시나리오와 독립 보안 리뷰, 운영 복구 검증은 아래 별도 게이트로 유지한다.

## 1. 계층

| 계층 | 도구/대상 | 필수 검증 |
|---|---|---|
| 도메인 | pytest | 순자산·기간·원리금·보험금·재고 계산 |
| DB/API | pytest + PostgreSQL | FK, 트랜잭션, 가계 격리, 충돌, 재시도 |
| 웹 | Playwright·브라우저 모델/공통 fixture | 폼, 조회·수정, 상태, 핵심 사용자 여정 |
| Android | Kotlin 단위·계측, 실기기 | bridge, 지문/키, 잠금·백업·서명 |
| 운영 | 별도 복구 환경 | 백업 복원, API/앱 호환, 장애 복구 |

## 3. 보험 트리·입력

비용 없는 처방 노드, 입원 합계와 설명용 수술비 분해, 부분 환불, 청구 없는 직접 지급,
여러 계약·여러 사건 배분·분할 입금·반환·치료와 정산 상태 분리를 검증한다.
부모를 자손 밑으로 이동, 다른 사건으로 참조 연결, 비용이 있는 노드의 무단 삭제는 실패해야 한다.
진료비 원본과 청구 연결 JOIN으로 SUM이 늘어나는 회귀 테스트를 둔다.

## 4. 보안 테스트

- 로그인 미인증/만료, 다른 가계 ID, revoked 기기, CSRF, 로그인 rate limit.
- 패스키 잘못된 RP/origin/challenge, 재사용 challenge, UV 누락.
- 카드 목록·HTML·Query cache·스크린샷 fixture·logcat·서버로그에 PAN 평문 없음.
- Android 네이티브 bridge는 비밀을 반환하지 않고 허용되지 않은 URL/ID를 거부.
- 잘못된 보관함 암호, AAD/tag 변조, nonce 재사용, key_version mismatch.
- 지문 취소/잠금/미등록/새 지문 등록/기기 잠금수단 제거/화면회전/백그라운드/강제종료.
- 생체인증 성공 플래그만 위조해도 비밀이 해제되지 않음.
- 앱 재설치·기기 이전·클라우드 백업·앱 내보내기에 CVC가 포함되지 않음.
- 새로운 구성원 및 기기 wrapping, 복구코드 교체, 키 회전 중 장애 복구.
- 외부 첨부 URL/경로조작/다른 사용자 파일/HTML 파일 업로드 실패.

## 5. 합성 데이터와 증거

기본 fixture는 부부 A/B, 공동 가계 H1, 공격 검증용 별도 가계 H2, 더미 금융기관·의료기관만 사용한다.
보안 스크린샷과 로그는 더미 값으로 생성하고 실제 카드 정보를 CI artifact에 업로드하지 않는다.
테스트 결과에는 실행한 commit, 환경, 기기/API 수준, 명령, 성공/실패, 제한을 남긴다.
에뮬레이터 통과와 실기기 통과를 별도 필드로 기록한다.

## 6. CI와 실제 실행 결과 구분

현재 [.github/workflows/ci.yml](../.github/workflows/ci.yml)은 문서·도구, API lint/unit, 격리 문서 검사 도구,
웹 린트(ESLint·jsx-a11y)·타입·생성 계약, PostgreSQL API/migration, 웹 UI·실제 HTTPS, Android compile/unit job을 정의한다.
실기기 보안 테스트와 운영 복구는 별도 릴리스 게이트다.
lockfile 고정 설치, Action commit 고정, 최소 token 권한을 사용하고 외부 PR에 저장소 비밀을
주입하지 않는다. 이를 별도 의존성 취약점 검사나 전용 비밀 탐지 도구의 실행 결과로 표시하지 않는다.
로컬의 동일 명령 통과와 GitHub Actions 실행 결과는 별도로 기록한다. 실행기가 시작되지 않거나
로그/step이 없는 실패를 코드 검증 통과로 바꾸어 적지 않는다. 비밀 작업 브라우저 시험은
trace·screenshot·video를 끄며 실제 사용자 데이터는 사용하지 않는다.

## 7. v1 사용자 인수 시나리오

두 실제 Android 기기와 PC 브라우저에서 합성 데이터로 시작한다.
계좌/카드/연금/부채 등록 → 두 달 자산 비교 → 부부 수입과 고정비 → 보험계약과 사건/비용/지급 → 소모품 입고/교체를 완료한다.
양쪽 계정의 갱신·충돌·권한, 비밀 표시·복구, 백업 후 새 서버 복원을 검증한다.
7개 영역 중 하나라도 빠지면 전체 v1 인수를 완료하지 않는다.
