# Android 로컬 CVC의 사용자 선택 활성화

상태: 채택 · 2026-10-25 · R-10/R-11/R-12 · SB-030 · [Issue #39](https://github.com/jihoon22-lee/SallimBook/issues/39)

## 배경과 결정

이전 제품 요구사항은 일반 CVC 저장·조회 코드를 닫고 두 Galaxy 실기기 인수 뒤 여는 순서였다.
2026-10-18 사용자는 실제 기기 시험과 결과 제출 대기를 개발 작업에서 제거하고 직접 시험하여
발견한 문제를 새 이슈로 등록하기로 했다. #39는 일반 배포의 기능 활성화·사용자 선택 UI·서명 APK
갱신만 추적하도록 범위가 변경됐다. 2026-10-24 전체 잔여 구현 뒤 운영 배포 요청에 따라 이 작업을 수행한다.

기존 `LOCAL_CVC_ACCEPTANCE_VERIFIED=false`를 true로 바꾸어 미수행 인수를 통과한 것으로 표시하지 않는다.
일반 `vault.v1` 저장소에만 로컬 CVC를 허용하는 `NativeVaultCvcPolicy`로 배포 가용성을 표현한다.
다른 namespace의 합성 검사에는 기존 debug Activity 소유자와 정확한 binding 검증이 계속 필요하다.
release에는 합성 활성화 상태·fixture·실패 주입이 없다.

사용자는 Android 보관함 또는 카드 상세에서 입력·수정, 열람, 삭제 화면을 선택한다.
저장은 선택 사항이다. 네이티브 화면의 미선택 동의란, 직접 입력, 매번 실제 강한 생체인증과
동일 CryptoObject의 키 연산을 모두 거쳐 저장한다. 웹에서 동의하거나 서버 설정으로 켜는 경로는 없다.

## 유지하는 경계

- CVC 입력·평문·표시는 네이티브 화면에만 존재하며 JS에는 동작과 카드 ID, 완료/취소 상태만 전달한다.
- 서버 schema/API·웹 입력·브라우저 저장소·로그·사용자 export·운영 백업에 CVC 경로를 추가하지 않는다.
- 기기 키와 암호문은 가계·사용자·구성원·기기·키 버전·카드·secret ID/revision에 묶는다.
- 앱 잠금과 보관함 키 사용 인증을 구분하며 취소·잠금·화면 이탈·늦은 callback은 비밀을 표시하지 않는다.
- 삭제는 명시적으로 확인한다. 새 기기·재설치·키 무효화 후에는 직접 재입력하며 서버 복구를 제공하지 않는다.

## 검증 수준

[별도 보안 검토와 회귀 기록](../testing/local-cvc-release.md)에 실행 결과를 기록한다.
두 Galaxy의 실제 생체인증 성공·제조사 이전·화면 캡처·입력기 동작은 사용자 후속 시험이며
에뮬레이터/JVM/브라우저 결과를 그 증거로 대신하지 않는다. 이 결정만으로 v1.0.0 출시나 외부 보안 인증을 주장하지 않는다.
