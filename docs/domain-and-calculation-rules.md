# 도메인·계산 규칙

이 문서의 규칙은 제품 설계 결정이다. 세무·회계·보험 보상에 관한 자문이나 보험금 자동 산정 기준이 아니다.

## 1. 공통

원화는 정수 원 단위로 저장하고 API에서는 `"1200000"`처럼 문자열로 전달한다.
소수와 외화 참고금액은 Decimal로 별도 관리한다. PostgreSQL의 정확한 numeric 자료형은 [S10](references.md)을 참고한다.
모든 날짜는 화면에서 Asia/Seoul 기준, timestamp는 UTC로 저장한다.
월 귀속값은 `YYYY-MM`이며 DB에서는 해당 월 1일인 date로 정규화한다.
자산 기준일, 거래가 발생한 날, 앱에 기록한 시각을 서로 대체하지 않는다.

## 2. 자산과 스냅샷

`총자산 = 포함된 자산의 가계 보유금액 합`

`총부채 = 포함된 부채의 남은 잔액 합`

`순자산 = 총자산 - 총부채`

부채 잔액은 양수로 저장하고 집계 시 차감한다. 음수 잔액이 필요한 마이너스통장은 자산 음수와 부채 중 하나의 모델만 사용한다.
v1 기본은 한도대출의 실제 사용액을 부채 항목으로 기록하는 것이다. 한도 자체는 부채가 아니다.

### 소유와 중복

금융계좌는 자산 항목과 1:1 연결된다. 자산 화면과 계좌 화면에서 금액을 표시할 때는 같은 자산 ID의 선택 월 스냅샷을 원천으로 사용한다.
자산·계좌 목록 API는 등록정보(metadata)를 조회하며 현재 잔액을 반환하지 않는다. 목록의 등록정보로 월 평가액을 추정하지 않고,
월 기록·비교 조회의 서버 `owned_amount_krw`를 가계 보유분으로 표시한다. 전체 입력액과 지분은 상세에서 확인한다.
증권계좌의 총 평가액을 등록했다면 현금/ETF/펀드 구성은 참고 정보일 뿐 별도 합산하지 않는다.
공동 명의 주택은 가계 자산 1건이다. 소유자를 두 사람으로 표시해도 두 배 합산하지 않는다.
부동산 금액 입력 방식은 `전체 평가액 × 가계 지분` 또는 `이미 가계 보유분인 금액` 중 하나를 명시한다.
지분 적용 후 원 미만은 HALF_UP으로 반올림하며, 이미 보유분인 금액에 다시 지분을 곱하지 않는다.
국민연금 예상 월수령액 같은 미래 흐름은 현재 자산 합계에서 제외한다.
보험료 납입 누계는 자산이 아니다. 확인된 환급·적립 평가액만 자산으로 연결한다.
가전 구매금액은 기본 순자산에 포함하지 않는다.

### 월 기록 상태

`draft → confirmed → reopened(new revision) → confirmed`.
전월값 불러오기 행은 `carried_unconfirmed`, 사용자가 금액 또는 변동 없음을 확인하면 `verified`.
누락은 null이고 0원이 아니다. 미확인 행을 포함한 합계에는 임시 표시와 확인 건수를 붙인다.
모든 유효 항목의 기준일·금액·확인이 갖춰져야 월 확정이 가능하다.
전월 기록이 없으면 증감을 0으로 표시하지 않고 비교 불가로 표시한다.

### 비교 범위와 정정

총 순자산 차이는 두 월의 실제 확정 합계 차이로 보여주되 비교 대상이 달라지면 경고한다.
별도로 양쪽 월에 공통으로 존재하는 항목의 동일 범위 증감을 제공한다.
기존 보유 자산의 뒤늦은 등록, 신규 취득, 매각, 해지 사유는 구분한다.
새로 등록했다는 사실만으로 실제로 이번 달 얻은 자산이라고 추정하지 않는다.
과거 값 정정은 새 revision을 만들고 이전 확정값과 사유를 보존한다.

SB-012의 월 작성 대상은 해당 월에 하루라도 보유한 자산이다(`started_on <= 월말`, 종료일 없음 또는 `ended_on >= 월초`).
종료한 월의 마지막 잔액도 직접 확인하며 자동으로 0원을 채우지 않는다. 그 다음 월부터 작성 대상에서 제외한다.
기준일은 선택 월 안의 실제 확인 날짜이며 미래 날짜는 거부한다. 월말과 다른 날짜가 있으면 확정 전에 명시적으로 확인한다.
전월의 마지막 확정본을 복사하되 기준일은 비우고 모든 복사 금액을 미확인으로 둔다. 입력 기준이 whole/owned 간에
바뀌면 이전 원금액을 추정 변환하지 않고 미입력으로 남긴다.
정정본은 과거 확정 시점의 이름·소유·지분·평가 기준·합산 여부를 복사한다. 현재 자산 범위로 바꾸는 것은 별도 명시 동작이다.
같은 자산 ID라도 가계 지분이 달라지면 비교 범위 변경으로 표시하고 동일 범위 증감에서는 제외한다.
정규화된 가계 보유금액의 전체 증감은 그대로 제공하며, 소유 지분 확대를 투자 수익으로 해석하지 않는다.

SB-013 비교·추이는 현재 revision의 상태를 사용한다. 정정 중이면 그 달의 확정 차트값과 비교 증감은 null이고,
관찰값을 별도로 보여준다. 소유자·분류 필터도 당시 snapshot에 적용하므로 필터 대상 변경은 범위 변화다.
종료로 다음 달 대상에서 빠진 항목은 해당 월 값 null이며, 잔액 0을 직접 확인한 기록과 다르다.
기준일이 월말이 아니거나 여러 날짜가 섞이면 실제 날짜를 함께 경고한다.
순자산 증감률은 이전 순자산이 양수이고 두 월이 확정된 경우에만 `(현재 - 이전) / 이전 × 100`을
Decimal·HALF_UP 소수 둘째 자리로 표시한다. 이전 0원/음수는 증감률 null과 사유를 표시하며,
원 단위 변화는 그대로 보존한다. 이를 투자 수익률·저축률로 부르지 않는다.

## 3. 부분적인 금전 기록과 잔액의 독립

v1의 `cash_records`는 수입·의료비·보험금·고정 납부라는 제한된 사실 기록이다.
전체 입출금 장부가 아니며 계좌 잔액을 계산할 수 없다.
어느 화면에서 입력하든 원본 금전 기록은 한 번만 생성한다. 월 수입은 원본에서 파생하는 조회 결과다.
보험금 수령 입력과 월간 수입 수동 입력을 두 번 만들지 않는다.

수입 화면은 근로/부수입과 보험금 유입을 구분한다. 환불을 급여 수입으로 분류하지 않는다.
`등록 수입 - 고정 납부`는 변동 소비·등록되지 않은 거래를 반영하지 않은 참고값이다.
이를 저축액·가처분소득·총 월지출 또는 순자산 증가액이라고 부르지 않는다.
월합계 수입 입력은 `precision=month`를 표시하며 실제 입금일을 임의로 만들어내지 않는다.
같은 수입을 월합계와 일별 내역으로 중복 입력하지 않도록 중복 의심 안내와 전환 기능을 제공한다.

## 4. 고정 납부

### 금액 구조

대출 원리금 1,000,000원 = 원금 700,000원 + 이자 300,000원인 경우:
고정 현금 납부액은 1,000,000원, 소비성 비용은 300,000원이다.
원금을 갚았다고 기록해도 월 부채 스냅샷을 자동 차감하지 않는다.
보험료·통신비·구독은 기본 비용, 연금 납입은 자산이동으로 구분할 수 있다.

### 규칙과 실제 회차

규칙은 납입 주기/기준일/금액/수단을 가진다. 회차는 그 규칙이 특정 날짜에 발생한 예정 건이다.
실제 납부는 회차와 연결된 금전 기록이다. 규칙 자체를 월 지출에 더하지 않는다.
월 주기의 31일 규칙은 짧은 달의 말일로 보정하되 다음 달에는 원래 31일 기준으로 돌아온다.
연 주기의 2월 29일은 평년 2월 말일 처리라는 제품 정책을 명시한다.
공휴일·영업일 이연은 금융기관과 다를 수 있어 자동 단정하지 않고 예정일 직접 수정으로 처리한다.
한 회차에 분할 납부가 가능하며 `미납 / 일부 납부 / 납부 확인 / 건너뜀`을 표시한다.
금액이 달라지면 실제 금액을 기록하고 차이를 보여준다. 현재 규칙을 바꿔 과거 기록을 덮어쓰지 않는다.

### 카드로 납부하는 고정비

구독의 카드 승인 예정일과 계좌에서 카드 대금이 나갈 날은 다르다.
v1에는 전체 카드 명세서가 없으므로 카드 결제일별 모든 출금액을 정확히 안다고 표시하지 않는다.
고정비 화면에는 '등록된 정기 결제 기준'이라고 표시하고 확정되지 않은 출금 예상일은 예상으로 표시한다.
카드 청구 합계 기능을 후속 추가할 때 구독 결제와 카드 대금 납부를 소비로 이중 집계하지 않는다.

### 보험료 연결

보험계약과 납부 규칙은 1:N일 수 있다(별도 특약 또는 납부 방식 분리).
납부 금액/주기/수단의 기준 정보는 recurring rule version에 하나만 둔다.
보험 상세의 보험료 수정은 동일한 규칙 변경 서비스를 호출한다. 두 독립 금액 칼럼을 수동으로 맞추지 않는다.

## 5. 보험 비용·청구·지급

### 비용의 합산 단위

실제 본인이 지불한 금액을 비용 기록으로 등록한다. 병원의 총진료비, 공단 부담액, 비급여/급여 분류는 설명 정보다.
입원 영수증 합계 860,000원에 포함된 수술비를 새 지출로 다시 등록하지 않는다.
한 비용은 한 진료 노드에 귀속하고 하위 명세가 있으면 합계의 분해로 다룬다.
부모 노드 합계는 하위 비용을 집계하며 별도 원본 비용으로 저장하지 않는다.
처방전처럼 비용이 없는 노드도 존재할 수 있다.

### 수령과 반환

`순의료비 = 실제 의료 지불금 - 병원/약국 환불금`

`순보험금 수령 = 실제 지급 입금 - 보험사 반환금`

`사건 순현금부담 = 순의료비 - 순보험금 수령`

보험료는 사건 비용에 포함하지 않는다. 접수금액·청구금액·심사예상액은 수령액에 넣지 않는다.
정액 보장과 의료비 보전 지급은 따로 표시하며 합산 순현금부담도 제공한다.
보험금이 비용을 넘어서면 결과가 음수일 수 있다. 0으로 강제 보정하거나 보험 과지급으로 단정하지 않는다.
보험사 청구액은 진료비와 다를 수 있으므로 직접 입력하며 보상 적정성을 자동 판단하지 않는다.

### 다중 관계

사건 1건에 여러 보험계약 청구가 가능하고 같은 비용을 여러 청구의 근거로 연결할 수 있다.
청구별 연결 비용을 모두 합한 값을 사건 총비용으로 사용하지 않는다.
실제 입금 1건이 여러 청구/사건에 해당하면 배분 행으로 나눈다. 배분 합계는 입금 원본과 정확히 일치해야 한다.
청구 정보를 모르면 청구ID 없이 사건과 계약에 직접 배분할 수 있다.
반환금도 원래 지급·배분에 연결해 기록한다. 입금 원본을 삭제해서 반환처럼 보이게 하지 않는다.

## 6. 재고와 교체

`현재 재고 = 기초/입고/반품 유입 - 사용/반품 출고 + 사유 있는 조정`.
제품 호환 소모품을 SKU/규격 단위로 공용 재고 관리하고 각 기기 교체 주기는 별도 관리한다.
필터 3개 입고 → 재고 +3, 교체일 변화 없음.
필터 1개 교체 → 재고 -1, 해당 기기의 교체일과 다음 확인일 갱신.
동시 교체 요청은 재고 행 잠금과 멱등키로 음수 재고를 방지한다.
재고가 없으면 구매 필요, 재고가 있으면 교체 필요를 구분한다.
교체를 취소하면 보정 movement를 남겨 재고와 일정을 복원하고 원래 이력을 지우지 않는다.
교체 때 해제한 직접 지정 다음 확인일은 그 교체를 취소하면 되살린다. 해제한 뒤 기기별 연결 설정을 한 번이라도 바꿨다면 바꾼 설정을 유지하고, 해제 정보가 없는 0016 이전 교체도 되살리지 않는다.
곧 교체는 다음 확인일이 서버 오늘(Asia/Seoul) 다음 날부터 7일 안에 있는 연결이다. 오늘이거나 이미 지난 확인일은 교체 확인 필요다.
교체 주기는 사용자가 정한 관리 기준이며 제조사 보증/의학적 권장 주기라고 주장하지 않는다.

## 7. 삭제

참조 없는 오등록은 확인 후 실제 삭제할 수 있다.
사용 이력이 있는 카드·계좌·보험·자산·제품은 기본 종료/보관 처리하고 새 연결에서는 제외한다.
비밀 제거는 일반 종료와 다르다. 카드 메타데이터·과거 결제 참조를 보존해도 PAN 암호문과 기기 CVC를 별도로 폐기할 수 있어야 한다.
오프라인 기기의 원격 CVC 삭제는 즉시 보장할 수 없으며 다음 연결 시 폐기 지시와 기기 초기화를 안내한다.
