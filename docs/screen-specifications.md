# 화면 구조·상호작용 명세

SB-003에서 아래 26개 경로와 생활비·보험·더보기 허브, 5개 모바일 탭·PC 사이드바를 연결했다.
현재 각 화면은 준비 상태를 명시하며 업무 기록·저장 기능을 제공하지 않는다.
직접 진입·새로고침·안전한 뒤로가기, Seoul 월 선택 유지, 키보드 본문 이동과 좁은 화면 확대를 시험한다.
모바일 viewport 시험은 실기기 Android 동작 검증과 구분한다.

## 1. 공통 탐색

Android 하단 탭: **홈 / 자산 / 생활비 / 보험 / 더보기**.
자산 탭에서 계좌, 생활비 탭에서 수입·고정 납부·카드, 더보기에서 가전·소모품·설정으로 이동한다.
홈의 소모품 카드를 누르면 상세 관리 화면에 바로 연결한다. 필수 기능은 최대 두 번의 메뉴 이동으로 접근한다.
PC는 동일 경로를 좌측 사이드바로 펼쳐 표시한다. PC용 별도 DB나 별도 기능 모델을 만들지 않는다.

## 2. 홈

```text
SallimBook                              설정 / 잠금
[ 2026년 10월 ▼ ]                 기록 6/8 확인
┌ 월간 자산 ───────────────────────────────────┐
│ 순자산 / 총자산 / 부채 / 전월 대비            │
│ 미확인 2개 · 임시 합계 · [이번 달 확인]       │
│ 최근 월 추이 / 항목별 변화 / 범위변경 안내     │
└──────────────────────────────────────────────┘
┌ 소모품 · 오늘 기준 ───────────────────────────┐
│ 교체 필요 · 곧 교체 · 재고 부족                │
│ 필터 [교체 기록] / 브러시 [입고 기록]          │
└──────────────────────────────────────────────┘
이번 달 수입 | 등록 고정 납부 | 진행 보험 사건
```

PC에서는 자산과 소모품을 큰 두 열로 배치하고 모바일에서는 자산 요약 다음 소모품 목록을 둔다.
차트보다 기록 확인·소모품 교체 동작을 우선한다. 긴 차트가 소모품을 지나치게 아래로 밀지 않게 한다.
선택 월은 자산·수입·정기 납부에 적용한다. **소모품은 과거 월을 선택해도 오늘 상태**다.
수입·고정비 금액은 '등록 기준'이라고 표시한다.

브라우저 새로고침·직접 경로·Android 뒤로가기에서도 같은 상태 규칙을 적용한다.
유효한 `/assets/months/YYYY-MM` 경로로 직접 진입하거나 새로고침하면 공통 선택 월도 해당 월로 맞춘다. 자산 목록으로 돌아와도 그 월을 유지한다.
비밀 표시 화면은 주소·query parameter에 카드번호나 암호문을 넣지 않는다.

## 4. 화면별 필드·검증

### 자산·계좌 (UI-04~09)

자산: 이름, 자산/부채, 분류, 소유자(구성원/공동), 금액 기준, 가계 지분, 시작/종료일, 메모.
계좌: 금융기관 자유 입력, 계좌 유형, 계좌명, 번호, 용도, 개설/종료일.
연금저축·IRP·DC·ISA는 목록 필터와 등록 선택지에서 숨기지 않는다.
스냅샷: 해당 월, 기준일, 평가/잔액, 확인 상태, 변경 사유.
수입/납부가 등록된 계좌 상세에서도 잔액은 별도 확인치라고 표시한다.
계좌번호는 기본 마스킹, 전체 보기에는 서버 재인증을 적용한다.

입력되지 않은 금액에 `0`을 기본값으로 넣지 않는다.
전월값 일괄 확인은 실제 항목을 검토하는 확인 절차가 있어야 하고 버튼 오탭으로 확정되지 않게 한다.
월 확정 시 미확인 항목, 비교 범위 변화, 기준일 불일치를 요약한다.
정정 시 사유 필수, 이전 확정 revision을 조회할 수 있다.

### 수입·고정비 (UI-10~13)

수입: 구성원, 월, 실제 입금일(선택), 날짜 정밀도, 종류, 금액, 입금계좌, 메모.
보험금 유입 행은 사건으로 이동하는 링크를 제공하고 이 화면에서 별도 복제하지 않는다.
고정비: 이름/종류, 월·연·주기, 기준일, 예상금액(미정 가능), 시작/끝, 납부수단, 계약/대출 연결.
AI 구독 등 외화 청구는 청구통화·참고금액과 원화 예정/실제 금액을 분리한다. 실시간 환산이 있다고 표시하지 않는다.
실제 납부: 납부일·금액·수단, 원리금 분리(해당 시), 사유. 기존 예정은 남긴다.
연간 구독은 월 고정비와 구분하고 납부월에 예상액이 잡히도록 한다.
카드 승인 예정일과 계좌 출금 확정일을 혼동시키는 '이번 달 총 출금' 문구는 금지한다.

### 카드·보관함 (UI-14~16)

일반정보: 소유자, 카드사/카드명, 별칭, 신용/체크, 결제일, 결제계좌, 상태.
민감정보 등록은 별도 보안 화면: 전체 PAN, 유효기간, Android 로컬 CVC(선택).
기본 카드 목록은 마지막 4자리만 표시한다. 유효기간은 `**/**`, 보안코드는 `***`로 표시한다.
Android는 네이티브 보안 화면에서 입력과 표시를 수행하며 JS는 저장/취소 결과만 받는다.
PC는 보관함 암호를 입력하는 별도 화면으로 PAN/유효기간을 확인하며 CVC 항목은 '이 기기에서 제공하지 않음'으로 안내한다.
해지 시 연결된 정기결제를 나열하고 변경 또는 사용종료 확인을 받는다.
일반 카드 종료와 '보관된 비밀 제거'를 구분한다.

### 보험 (UI-17~21)

계약: 보험사, 상품명, 증권번호, 계약자/피보험자/수익자, 보장/납입 기간, 보장 항목, 상태, 문서.
보험료는 연결 고정비 규칙을 읽고 편집한다.
사건: 사건명, 환자, 진단명/코드(선택), 시작/종료일, 치료상태, 정산상태.
트리: 외래, 입원, 수술, 처방, 약국, 추적 외래, 사용자 그룹.
노드별 하위 추가·이동·수정·증빙·비용 기록을 제공한다. 드래그 외에도 부모 선택으로 이동 가능해야 한다.
깊은 트리는 모바일에서 breadcrumb와 상위 이동을 제공하며 UI 기본 표시 깊이는 3~4단계로 접는다.
같은 사건 내에서만 이동하고 자손 아래로 부모를 옮기는 동작은 거부한다.

비용: 실제 지불금·결제수단·날짜·영수증, 필요 시 설명용 명세 분해.
청구: 계약·대상 비용·접수일·청구액·상태·참고번호.
지급: 실제 입금 총액·일자·계좌·사건/계약/청구·급부유형별 배분.
청구ID 없이 지급만 먼저 등록할 수 있다. 배분 잔액이 0원이 아니면 확정할 수 없다.
상단에 의료 지불금, 환불, 순의료비, 순보험금, 순현금부담을 명확히 표시한다.

### 가전·소모품 (UI-22~25)

제품: 명칭/제조사/모델/장소/구매일/금액/판매처/보증기한/문서.
소모품: 이름/규격/단위/공용 재고/부족 임계값/호환 기기/기기별 주기.
입고: 실제 날짜/수량/선택 가격·구매 링크. 교체일은 바뀌지 않는다.
교체: 기기/소모품/날짜/사용수량, 저장 직전 재고를 재검증한다.
재고 조정: 사유 필수. 교체 취소는 반대 재고 이력을 남긴다.
보증·교체 알림은 홈과 인앱 목록이 v1 필수, 푸시 전달 보장은 후속이다.

## 5. 상태와 접근성

모든 화면에 loading, empty, error, stale, forbidden, conflict 상태를 정의한다.
빈 화면은 다음 행동을 안내하고 검증 실패는 입력값을 가능한 범위에서 유지한다.
잠금/로그아웃 시 비밀·민감 입력은 초기화한다.

버튼은 충분한 터치 영역, 명확한 레이블, 키보드 초점, TalkBack 이름을 갖춘다.
색만으로 수입/지출·완료/미확인을 구분하지 않는다. 숫자 정렬과 단위를 일관되게 유지한다.
핀치/글꼴 확대를 막지 않고 가로 스크롤 없이 핵심 필드를 입력할 수 있게 한다.
PC는 키보드만으로 트리 이동·폼 저장·대화상자 종료가 가능해야 한다.

## 6. PC와 Android의 의도된 차이

핵심 금융/보험/생활 기능은 같다. 인증 수단과 기기 로컬 비밀은 다를 수 있다.
Android의 지문/CVC/캡처 제한을 PC에서 동일하게 보장한다고 광고하지 않는다.
PC는 넓은 비교표와 다중 컬럼, Android는 빠른 기록과 단계별 입력을 우선한다.
