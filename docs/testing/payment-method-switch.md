# 결제수단 일괄 변경 검증

대상: [#175](https://github.com/jihoon22-lee/SallimBook/issues/175), 승인된 P18. 요구사항 R-01·R-02·R-08·R-09·R-18·R-19·R-22.

## 동작과 범위

카드/계좌 사용 종료 검토에서 **연결 규칙 결제수단 바꾸기**를 열고 새 계좌/카드, 서울 기준 오늘 이후 적용일을 선택한다. 현재·미래 조건의 기간·금액·주기와 변경 예정 회차 수, 적용일 이전·납부·수동 예외 회차의 보존 건수를 확인한 뒤 규칙별로 선택한다. 계좌는 직접 납부 규칙만 대상으로 한다. 결제계좌로 연결된 카드의 승인 계획과 카드 자체의 결제계좌는 별도 카드 상세에서 확인한다.

각 규칙은 별도 원자적 명령으로 저장한다. 성공한 행을 보존하고 실패·충돌한 행만 새 미리보기로 교체한다. 재검토한 행은 다시 선택해야 한다. 응답 유실은 같은 본문과 멱등 키로 재확인한다. 화면을 떠나면 아직 시작하지 않은 행은 전송하지 않는다. 이미 전송한 요청은 서버에서 완료될 수 있으므로 다음 조회에서 연결을 다시 확인한다. 처리 중에는 종료 저장을 막으며, 처리 후 종료 영향과 확인 동의를 새로 받는다.

금융기관·서비스의 실제 자동이체/카드 변경을 실행하지 않는다. 기존 종료 영향 확인·감사·충돌 정책을 유지하고 계좌 잔액이나 월간 자산을 가감하지 않는다.

## 서버 불변식

- `/payment-switch/preview`는 읽기 전용 POST이며 쓰기 부작용·멱등 기록을 만들지 않는다. `cursor`와 `limit=1..200`으로 규칙을 조회한다.
- `/payment-switch/rules/{rule_id}`는 가계 쓰기 잠금 안에서 권한, If-Match, 현재 연결, 적용일, 목표 수단의 사용 가능 여부와 행별 digest를 검증한다. 다른 가계의 원본·목표·규칙·커서는 404다. source/target 권한은 멱등 재전송에서도 확인한다.
- digest는 요청 범위·원본/목표 버전·해당 규칙 전체 조건·회차 버전·활성 납부를 묶는다. 규칙 버전이 그대로여도 회차 납부가 추가되면 409다. 다른 행의 성공 때문에 나머지 미리보기가 무효화되지는 않는다.
- 현재 기간은 적용일에 분할하고, 해당 원본 결제수단을 쓰는 이후 기간은 같은 금액·주기·날짜·메모·부채 연결을 복제하여 결제수단만 바꾼다. 다른 수단의 미래 기간은 그대로 둔다. 원래 조건은 이력으로 남고 기존 재생성 로직을 통해 생성 범위를 유지한다.
- 적용일 이전 회차, 일부/전체 납부 기록이 있는 회차, 건너뛰기·수동 완료·날짜 이동 예외는 기존 snapshot과 revision을 유지한다. 미래 조건이 교체되어도 해당 예외 회차는 이전 버전을 참조한다.
- 첫 규칙 시작일 당일/이전에는 최초 조건을 철회하지 않는다. 해당 행은 `INITIAL_PERIOD_START`로 선택을 막고 첫 시작일 다음 날 이후를 안내한다. 이는 기존 DB 이력 보호 정책과 일치하며 새 마이그레이션은 없다.

## 실행 근거

합성 데이터만 사용한다. 실기기 인수는 기존 사용자 결정에 따라 사용자가 담당한다.

- `pnpm test:database services/api/tests/test_payment_switch.py -q`: 14건 통과. 미래 요금·메모·주기 보존, 과거·부분 납부·수동 회차 원본 불변, 카드/계좌 간접 연결 구분, 다른 수단의 미래 조건 보존, 페이지, 닫힌 목표, 날짜 경계, 다른 가계, 부부 동시 저장 200/409, 재전송·키 재사용 검증. 모델 차이 없음 및 마이그레이션 역전/재적용 포함.
- `pnpm test:web payment-switch.spec.ts payment-closure.spec.ts cashflow-native-ui.spec.ts cashflow-native-bridge.spec.ts`: 44건 통과. 웹/Android 디스패치, 행별 재검토, 같은 키 재시도, 입력 변경 시 미리보기 폐기, 종료 저장 차단, 화면 이탈 후 후속 요청 중단, 320px·큰 글자·어두운 화면 포함.
- `uv run --project services/api pytest services/api/tests -m 'not database' -q`: 1,049건 통과. DB 주소가 없는 별도 23건은 skip, database 표식 677건은 제외했으며 실제 DB 검증은 위 명령으로 따로 수행했다.
- `uv run --project services/api python scripts/test_web_auth.py --cashflow`: 실제 HTTPS/API/PostgreSQL 통과. 카드 종료 검토에서 4,321원 규칙을 계좌로 변경하고 기존 카드 기간·새 계좌 기간·원래 금액·서울 적용일, 후속 카드/계좌 종료와 독립 스냅샷을 확인했다.
- Android debug 빌드와 JVM 474건 통과. 새 고정 경로·헤더, 잘못된 날짜/동일 수단/추가 비밀 필드 거부, 응답의 원본 수단·기간·규칙 ID 결합을 확인했다. 이 결과는 실기기 실행을 뜻하지 않는다.

초기 UI 테스트의 라벨 탐색과 이탈 확인 대화상자 처리, JVM 테스트의 응답 거부 오류 코드 기대값은 테스트에서 수정했다. 제품의 권한/원본 보호 정책을 완화하지 않았다. 형 검사·ESLint·Prettier·Ruff·생성 계약 및 문서 검사도 통과했다. `./gradlew --no-daemon :app:assembleDebugAndroidTest`도 통과했다. Android 계측용 빌드는 앱 모듈을 대상으로 하며, 모듈을 지정하지 않은 `assembleDebugAndroidTest`는 사용하지 않는 Cordova 라이브러리 테스트의 Kotlin 중복 의존성 때문에 실패했다. 이 서드파티 테스트 구성은 변경하지 않았다.
