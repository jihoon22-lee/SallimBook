# 최초 금융정보 입력에서 드러난 보완 사항

날짜: 2026-10-31. 사용자 요청: 추가 실데이터 입력을 중지하고 부족한 부분을 조사·수정·검증한 뒤 재개한다.
실제 자료·명의·번호·비밀은 이 문서와 Issue/PR/fixture에 포함하지 않는다.

## 확인된 문제와 완료 조건

1. **연회비 전용 필드 없음.** `annual_fee_krw`를 nullable 정수 원 단위 십진 문자열로 관리한다.
   null과 0원을 구분하고 메모를 보존한다. 실제 납부·월 잔액을 자동 생성/가감하지 않는다.
2. **가족카드 여부 없음.** `is_family_card`에 true/false/null을 허용한다. 표에 표시가 없다는 이유로
   false를 추론하지 않는다. 가족카드 여부만으로 본카드·결제계좌 연결을 추론하지 않는다.
3. **설정 버튼을 눌러도 다음 화면이 보이지 않음.** 보관함 보호 작업이 아래에 렌더링되지만
   스크롤/초점 이동이 없다. 열 때 작업 영역을 보여주고 키보드 초점을 이동한다.
   탭/창 이탈·제한시간 잠금은 유지하며 잠긴 상태에서 다시 시작할 동선을 명확히 한다.
4. **웹 CVC 입력 불가.** 사용자가 기존 로컬 전용 결정을 변경했다. 별도 ADR로 변경 이력을 남기고
   웹 보호 화면에서 선택적으로 입력·표시·수정·삭제하며 클라이언트에서 암호화한다.
   일반 카드 API·HTML 목록·React state·로그·평문 내보내기로 CVC가 흘러가지 않아야 한다.
5. **공유 포맷/Android 호환성.** 기존 SBV1은 CVC 없는 27바이트 고정 포맷이다. 버전이 있는
   새 포맷과 서버 envelope 검증, TypeScript/Kotlin 양쪽 구현, 키 회전·복구 경로를 함께 검증한다.
   구버전이 새 비밀을 모른 채 덮어써서 CVC를 잃는 동작은 거부한다.
6. **기존 로컬 CVC와 공유 CVC 구분.** 기존 Android 로컬 값을 무단 업로드/삭제하지 않는다.
   동기화 값과 기기 로컬 값의 출처를 구분하고 사용자가 명시적으로 선택하도록 한다.
7. **최초 입력의 반복 작업.** 일반정보와 보관함 입력을 연결하고, 여러 카드 비밀을 한 보호 작업에서
   입력할 수 있게 한다. 미리보기에는 비밀을 마스킹하고 카드 ID/소유자/끝자리로 대상을 검토한다.
   부분 성공 시 성공한 카드 재등록을 피하고 동일 암호문·멱등키 재시도를 사용한다.
8. **불확실한 원본 항목.** 상위 유형과 상세 유형이 충돌할 때 조용히 확정하지 않고 정규화 결과를
   보여준다. 금융사와 결제은행을 분리하고 모르는 결제일/계좌/개설일/잔액은 비워둔다.
   자산의 관리 시작일과 실제 계좌 개설일을 구분한다. 이미 등록된 항목은 보존한다.

## 구현 결정

기존 React/TypeScript, FastAPI/SQLAlchemy/Alembic, Kotlin 네이티브 보관함을 확장한다.
새 암호 알고리즘·키 저장소·평문 CVC 서버 필드를 만들지 않는다. CVC는 선택적인 공유 보관함
payload이며 동일 가계라도 보관함 공유를 받은 구성원만 해독한다. 암호화 운영 백업에는 해당
암호문이 포함될 수 있음을 명시한다. 현재 복구/백업 사본을 소급 삭제했다고 주장하지 않는다.

## 진행과 검증 경계

추가 실데이터 입력은 수정·검증 이후로 보류한다. 이미 등록한 일반정보와 계좌는 삭제하지 않는다.
테스트는 합성 자료만 사용한다. 서버 권한/충돌/멱등, TS/Kotlin 공통 벡터, 웹 잠금/실패 경로,
Android 빌드와 가능한 계측 시험, 독립 보안 리뷰를 진행한다. 실기기 미실행은 별도로 기록한다.
배포·정식 APK·실사용 입력 성공은 각각 별도 증거로 확인한다.
