# 보관함 상태·카드 진입 화면 검증

대상: SB-028~032, R-02/R-09/R-10/R-11/R-12/R-18. 생성 API 계약의 안전한
보관함 상태·공유 목록·키 회전 준비 현황을 일반 React 화면에서 조회한다.
암호·키·암호문·카드번호 전체·유효기간·복구코드는 이 화면의 상태에 넣지 않는다.

## 화면 동작

- `/vault`는 로그인 후 설정 전, 공유 전, 접근 가능, 접근 철회 상태를 구분한다.
  일반 가계 초대가 카드 비밀 자동 공유를 뜻하지 않음을 안내한다. 구성원 표시명과
  공유 요청의 발신/수신·만료·수락/취소 상태를 표시하며 cursor로 다음 목록을 읽는다.
- 현재 키 회전이 필요하면 새 카드 비밀 등록·수정과 공유 진입을 제한한다. 진행 중인
  회전은 카드·구성원·키 확인·복구 수단 준비 수를 보여 주고 계속하기/중단 검토를 제공한다.
  UI의 버튼 제한은 서버 권한·최신 버전 검증을 대신하지 않는다.
- 안전한 상태를 새로 읽는 동안과 실패한 뒤에는 이전 권한으로 작업 버튼을 계속 표시하지 않는다.
  401/앱 잠금은 공통 인증 계층이 화면을 해제한다. 요청의 원문 오류 메시지는 표시하지 않는다.
- 카드 상세의 일반정보 수정·사용 종료와 보관함 비밀 열람·수정·제거는 별도 진입이다.
  보관함 비밀이 있는 카드는 마지막 네 자리를 일반 편집에서 바꿀 수 없으며 카드 상세의
  보관함으로 안내한다. 별칭 등 일반정보 수정은 가능하다. 충돌 비교에서 새 비밀 등록을
  발견하면 최신 마지막 네 자리만 채택하고 다른 작성 내용은 유지한다.
- Android는 보호 화면에 action과 해당 resource ID만 전달한다. 완료/취소만 돌려받으며
  완료 후 안전한 metadata를 다시 조회한다. 동일 작업 중복 진입을 막고 화면 이탈 후 늦은
  응답으로 기존 화면을 다시 열지 않는다. HTTP나 웹 입력으로 우회하지 않는다.
- PC는 전용 보호 화면으로 연결한다. CVC/CVV 입력·열람·저장을 제공하지 않고 웹 캡처 제한의
  한계를 안내한다. Android 로컬 CVC 입력·열람은 실기기 보안 검증 전 비활성 상태임을 명시한다.
  이미 기기에 남은 CVC의 명시적 삭제는 카드 ID만 네이티브 보호 화면에 전달하여 제공한다.
  보관함 암호·복구코드·신뢰 기기를 모두 잃었을 때 기존 비밀을 복구할 수 없음을 설명한다.

## 검증 범위

`vault-overview.spec.ts`는 안전한 조회·마스킹·권한/회전 상태·페이지 연결·실패/만료·카드
일반정보 보존을 확인한다. `vault-overview-native.spec.ts`는 실제 React 버튼을 통해
네이티브 보호 화면 진입 인자를 확인하고 취소·세션 만료·키 무효화·앱 잠금·네트워크 실패와
늦은 완료를 확인한다. 합성 metadata만 사용하며 trace/screenshot/video 수집을 끈다.

이 검증은 네이티브 암호화·Keystore·생체 인증·백업 차단의 실기기 인수를 대신하지 않는다.
PC 보호 화면의 암호 처리·출력 수명 검증과 실제 서버 통합 결과도 별도로 기록해야 한다.

## 실행 기록

현재 추가 화면 시험은 보호 화면 구현 통합을 기다리고 있으며 아직 실행하지 않았다.
중간 `pnpm typecheck`는 미도착 `WebVaultAction` import 1건으로 실패했다.
다른 타입 오류는 출력되지 않았다. 통합 후 결과와 실행 명령을 갱신한다.
