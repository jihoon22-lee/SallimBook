# ADR — 별도 암호 없는 카드 상세정보

상태: 사용자 결정 채택. 날짜: 2026-10-31. 연결: #186, R-09/R-10/R-20.

## 사용자 결정

기존 자료를 입력할 때 별도 보관함 암호와 반복 확인이 실제 사용을 막았다. 사용자는
추가 암호 입력 없이 운영자가 직접 등록하고 앱에서 편하게 확인하도록 명시적으로 요청했다.
이 결정을 기존 클라이언트 보관함 경로에 대한 서버 관리 대안으로 구현한다.

## 저장과 접근

카드 기본정보와 분리된 `card_stored_details`에 번호·유효기간·선택적 CVC를 한 묶음으로
AES-GCM 암호화한다. 계좌·보험의 서버 필드 keyring을 사용하되 카드 상세정보 전용 AAD에
가계 ID, 카드 ID, 키 버전을 바인딩한다. DB 및 운영 백업에는 암호문만 저장한다.
운영 서버는 이 정보를 복호화할 수 있으므로 이 경로를 클라이언트 암호화나 E2EE로 부르지 않는다.

현재 유효한 공동 가계 로그인으로 입력·열람·수정·삭제할 수 있다. 보관함 암호, 별도 공유 수락,
최근 로그인 재인증은 요구하지 않는다. 기존 웹 Origin/CSRF, 세션·기기 잠금과 만료 검증,
가계 격리, 수정 버전 충돌은 유지한다. 별도 전용 API만 평문을 취급하고 일반 목록, 감사,
사용자 내보내기에는 번호·유효기간·CVC를 넣지 않는다. 요청·응답과 예외 본문을 로그로 남기지 않는다.

웹은 전용 화면의 DOM/ref에만 입력·표시한다. Android는 별도 네이티브 화면에서 처리하며
JS bridge에 평문을 반환하지 않는다. 열람은 최대 30초이며 화면 이탈/잠금 시 지운다.
입력 형식 오류는 해당 필드를 알려주고 같은 보호 화면의 다른 입력을 보존한다.

## 기존 보관함과 원문 보존

기존 보관함 키·복구 수단·암호문은 변경하지 않는다. 동일 카드가 두 저장 경로에 동시에
등록되어 서로 다른 번호를 표시하지 않도록 양쪽 쓰기를 차단한다. 일반 화면의 마지막
네 자리 변경도 저장된 상세정보와 불일치하지 않도록 제한한다.

번호의 공백·하이픈은 제거한다. 숫자 개수·유효기간·CVC 형식은 검사하되 Luhn 불일치로
자료 등록을 막거나 번호를 추측해서 수정하지 않는다. 카드 유효성 확인이나 결제 승인이
아닌 사용자 자료 정리 기능이다. CVC의 선행 0을 보존하고 null은 명시적 삭제로 처리한다.

## 검증과 운영

합성 데이터로 가계 격리, CSRF, 만료·철회, 수정 충돌, 암호문 치환, 로그·내보내기 제외,
웹/Android 보호 화면 잠금과 늦은 응답 폐기를 시험한다. 독립 보안 리뷰를 수행한다.
실제 자료 입력은 비공개 운영 절차에서만 수행하며 테스트·Git·이슈에 원문을 넣지 않는다.
추가 테이블 마이그레이션은 기존 자료를 옮기거나 지우지 않는다. 새 상세정보가 있으면
데이터를 삭제하는 다운그레이드를 거부한다.
