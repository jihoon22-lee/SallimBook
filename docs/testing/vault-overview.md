# 보관함 상태·카드 진입 화면 검증

> 2026-10-25 변경: 일반 Android CVC 입력·열람은 네이티브 저장 동의와 매회 강한 생체인증을
> 요구하는 선택 기능으로 활성화한다. [별도 보안 검토·회귀](local-cvc-release.md)를 참고한다.
> 아래의 비활성 gate와 시험 수치는 당시 기록이며 실기기 통과를 새로 주장하지 않는다.

대상: SB-028~032, R-02/R-09/R-10/R-11/R-12/R-18. 생성 API 계약의 안전한
보관함 상태·공유 목록·키 회전 준비 현황을 일반 React 화면에서 조회한다.
암호·키·암호문·카드번호 전체·유효기간·복구코드는 이 화면의 상태에 넣지 않는다.

## 화면 동작

- `/vault`는 로그인 후 설정 전, 공유 전, 접근 가능, 접근 철회 상태를 구분한다.
  일반 가계 초대가 카드 비밀 자동 공유를 뜻하지 않음을 안내한다. 구성원 표시명과
  공유 요청의 발신/수신·만료·수락/취소 상태를 표시하며 cursor로 다음 목록을 읽는다.
- 현재 키 회전이 필요하면 새 카드 비밀 등록·수정과 공유 진입을 제한한다. 진행 중인
  회전은 카드·구성원·키 확인·복구 수단 준비 수를 보여 주고 계속하기/중단 검토를 제공한다.
  UI의 버튼 제한은 서버 권한·최신 버전 검증을 대신하지 않는다.
- 안전한 상태를 새로 읽는 동안과 실패한 뒤에는 이전 권한으로 작업 버튼을 계속 표시하지 않는다.
  401/앱 잠금은 공통 인증 계층이 화면을 해제한다. 요청의 원문 오류 메시지는 표시하지 않는다.
- 카드 상세의 일반정보 수정·사용 종료와 보관함 비밀 열람·수정·제거는 별도 진입이다.
  보관함 비밀이 있는 카드는 마지막 네 자리를 일반 편집에서 바꿀 수 없으며 카드 상세의
  보관함으로 안내한다. 별칭 등 일반정보 수정은 가능하다. 충돌 비교에서 새 비밀 등록을
  발견하면 최신 마지막 네 자리만 채택하고 다른 작성 내용은 유지한다.
- Android는 보호 화면에 action과 해당 resource ID만 전달한다. 완료/취소만 돌려받으며
  완료 후 안전한 metadata를 다시 조회한다. 동일 작업 중복 진입을 막고 화면 이탈 후 늦은
  응답으로 기존 화면을 다시 열지 않는다. HTTP나 웹 입력으로 우회하지 않는다.
- PC는 전용 보호 화면으로 연결한다. CVC/CVV 입력·열람·저장을 제공하지 않고 웹 캡처 제한의
  한계를 안내한다. Android 로컬 CVC 입력·열람은 실기기 보안 검증 전 비활성 상태임을 명시한다.
  이미 기기에 남은 CVC의 명시적 삭제는 카드 ID만 네이티브 보호 화면에 전달하여 제공한다.
  보관함 암호·복구코드·신뢰 기기를 모두 잃었을 때 기존 비밀을 복구할 수 없음을 설명한다.

## 검증 범위

`vault-overview.spec.ts`는 안전한 조회·마스킹·권한/회전 상태·페이지 연결·실패/만료·카드
일반정보 보존을 확인한다. `vault-overview-native.spec.ts`는 실제 React 버튼을 통해
네이티브 보호 화면 진입 인자를 확인하고 취소·세션 만료·키 무효화·앱 잠금·네트워크 실패와
늦은 완료를 확인한다. 합성 metadata만 사용하며 trace/screenshot/video 수집을 끈다.

이 검증은 네이티브 암호화·Keystore·생체 인증·백업 차단의 실기기 인수를 대신하지 않는다.
PC 보호 화면의 암호 처리·출력 수명 검증과 실제 서버 통합 결과도 별도로 기록해야 한다.

## 실행 기록

`89db3de`의 보호 화면 본체를 통합한 뒤 다음 명령을 실행했다. API 오류 코드 병합에서는
문서 저장 quota 코드와 보관함 코드를 모두 유지했다. 별도 API/DB migration 변경은 없다.

```bash
pnpm typecheck
pnpm --filter @sallimbook/client exec playwright test --config playwright.documents.config.ts tests/vault-overview.spec.ts tests/vault-overview-native.spec.ts tests/cards.spec.ts tests/routing.spec.ts --workers=1
pnpm --filter @sallimbook/client exec playwright test --config playwright.documents.config.ts tests/vault-overview-native.spec.ts --grep 'native busy action' --workers=1
pnpm build
python3 scripts/validate_docs.py
git diff --check
```

- 타입 검사 통과. 본체 통합 전의 `WebVaultAction` import 오류는 해소됐다.
- 새 보관함 화면 40개와 기존 카드 20개·경로 16개, 합계 **76개 통과**(PC/Android 크기, 약 1.7분).
  네이티브 일반 진입 시험은 초기 설정·회전 재개/중단 외에도 카드/공유/복구/기기/CVC 삭제
  13개 진입의 action과 ID만 확인했다. 네이티브 HTTP 호출과 JS 비밀 입력은 없었다.
- 첫 실행의 늦은 응답 시험은 목적지인 기기 설정 화면에 잘못된 모의 응답 형식을 제공해
  콘솔 오류가 있었지만 기존 assertion은 통과했다. 목적지를 실제 fixture가 지원하는 카드
  상세로 수정하고 `pageerror`가 비어 있음을 검사하도록 보강했다. 이 시험을 두 화면 크기에서
  재실행해 **2개 통과**, 콘솔 오류 없음. 추가 변경은 시험 파일에만 있으며 전체 76개를
  다시 실행했다고 주장하지 않는다.
- 배포용 빌드 통과(151개 모듈). 주 JS 파일 859.33 kB/gzip 221.22 kB이며 기존의
  500 kB 초과 chunk 경고는 남는다. 이 빌드는 APK 실기기·정식 서명 인수가 아니다.
- 문서 링크/manifest 검사와 `git diff --check` 통과.

이 실행에서는 PC 보호 화면 내부의 실제 암호 입력·복호화·키 회전 요청을 별도로 시험하지
않았다. 해당 workflow의 독립 시험과 실제 서버 통합은 담당 구현의 결과를 확인해야 한다.
읽기 전용 소스 검토에서는 늦게 생성된 키/평문 소유권을 즉시 등록해 닫힌 수명에서 제거하고,
카드 표시 전 권한·카드 버전을 다시 확인하며, 화면 이탈·30초 제한에 DOM 출력을 지우는
경계를 확인했다. 대상 rotation ID 일치 검사와 부분 저장 재시도 후 완료 안내 보강점은
담당 구현에 전달했다. 이 소스 검토를 실행 시험이나 실기기 보안 인증으로 간주하지 않는다.
