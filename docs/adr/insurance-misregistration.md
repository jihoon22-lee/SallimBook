# 보험 오등록 계약·사건 삭제

상태: 승인된 제품 완성 계획 P08 구현 결정 · Issue #155 · R-13/R-14/R-15/R-18/R-19

## 결정

등록 직후의 잘못된 계약·사건을 명시적 확인 후 삭제할 수 있다. 가계 권한과
`If-Match`를 확인하며, 버전이 1이 아니면 변경 이력을 보존하기 위해 거부한다.
보장·보험료·진료·비용·청구·지급·첨부 등 현재 또는 보존된 참조가 있으면 FK로 거부한다.
비활성 보장·해제한 보험료/첨부 연결, 철회 청구, 무효 지급도 참조로 남는다.
계약의 평가액 자산 연결도 삭제를 막는다. 상태 변경은 별도 수정 동작이다.

사건 생성 시 최초 스냅샷(version 1)이 항상 기록되므로, 기존 RESTRICT FK와
무조건적인 이력 삭제 금지로는 빈 사건도 삭제할 수 없었다. `0020`에서 그 FK만
CASCADE로 변경한다. 부모 사건의 DELETE는 version 1에만 허용하고, 이력 트리거는
부모가 사라진 뒤의 version 1 삭제만 허용한다. 부모가 남아 있는 직접 이력 삭제,
모든 이력 UPDATE, version 2 이상의 이력 삭제는 계속 금지한다. 수정된 계약·사건의
DELETE는 서비스와 DB 트리거 모두 거부한다. 다른 참조 FK의 RESTRICT는 유지한다.

최초 생성 스냅샷만 오등록 사건과 함께 제거하며 생성·삭제 감사는 보존한다.
참조 없는 진료를 별도로 삭제한 뒤에는 그 진료의 감사도 그대로 남는다.
이 기능은 진료·금전 기록의 일괄 삭제나 감사 삭제를 제공하지 않는다.

## 동시성·재시도·마이그레이션

보험·금전·첨부 쓰기와 같은 가계 잠금 아래 검사하고 삭제한다. 참조 추가와
삭제가 경합해도 한쪽은 가계 잠금 또는 FK에서 거부된다. DELETE는 원본 ID를
사용하므로 재전송해 중복 금전 동작이 생기지 않는다. 성공 204, 이미 삭제됨 404,
수정 버전 충돌 409, 보존 조건 위반 409를 구분한다. UI는 이미 사라진 대상의
404를 삭제 완료로 취급한다. 충돌 후에는 최신 내용을 다시 읽고 삭제 확인을 다시 받는다.

기존 행을 지우거나 고치는 데이터 마이그레이션은 없다. downgrade는 FK를 RESTRICT로,
이력 트리거를 원래의 무조건 수정/삭제 금지로 복원한다. 이미 삭제한 오등록 기록을
복구하지는 않는다. 생성·삭제 감사는 upgrade/downgrade와 무관하게 남는다.
