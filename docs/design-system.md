# 디자인 시스템·사용성 원칙

모바일에서 빠르게 확인·입력하고 PC에서 넓게 비교한다. 화려한 금융 차트보다 신뢰할 수 있는 값과 다음 행동을 우선한다.

## 레이아웃

좁은 화면은 단일열, 넓은 화면은 사이드바+본문, 홈은 자산/소모품 2열.
브레이크포인트는 실제 레이아웃 테스트로 확정한다. 특정 휴대폰 해상도만 하드코딩하지 않는다.
숫자는 우측 정렬·고정폭 숫자, 표와 차트는 같은 값을 사용한다.
한 화면에서 표시 월/기준일/확인 상태를 항상 알 수 있어야 한다.

## 컴포넌트

MoneyInput(빈값/0 구분), MonthPicker, OwnershipPicker, PaymentMethodPicker,
VerificationBadge, StatusChip, AmountBreakdown, LinkedResourceCard,
MedicalTree, AllocationEditor, StockActionDialog, SecureActionButton,
ConflictDialog, EmptyState, ErrorRetry, AuditTimeline을 공통화한다.
SecureActionButton은 원문을 받지 않고 플랫폼별 보안 화면을 호출한다.

## 문구

'순자산 변화', '등록된 고정 납부', '확인된 보험금 수령', '전월값·미확인', '오늘 기준'처럼 데이터 한계를 드러낸다.
확인되지 않은 값을 '실제 잔액', '총 소비', '저축액', '보험금 예상 확정'이라고 표시하지 않는다.
내부 테이블명·암호 용어를 일반 화면에 과도하게 노출하지 않는다.
잠금 실패는 비밀을 포함하지 않는 설명과 안전한 다음 행동을 제공한다.

## 접근성

터치 목표 최소48dp 수준을 설계 목표로 삼고 실제 기기에서 여백과 오탭을 확인한다.
손쉬운 한손 동작, 충분한 글자 크기, 폰트 확대, TalkBack, 키보드 동작, 고대비를 검증한다.
색만으로 금액의 의미를 나타내지 않고 증가/감소 텍스트를 병행한다.
트리 이동은 드래그 전용으로 만들지 않는다. 긴 폼은 논리적 단계로 나누고 필수값을 최소화한다.
다크 모드를 기본 지원하며 시스템 설정을 따른다. 특정 사용자 건강 상태를 UI 요구의 근거로 노출하지 않는다.

## 테스트 기준

작은 Android 화면, 큰 화면/태블릿 레이아웃, PC, 글꼴 확대, 느린 네트워크, 긴 한글 상품명,
0원/큰 금액/음수 순부담, 깊은 사건 트리, 소모품 품절을 합성 데이터로 확인한다.
